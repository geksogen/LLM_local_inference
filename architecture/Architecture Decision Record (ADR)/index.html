ADR 001: Архитектура локальной LLM-инфраструктуры на базе Strata Engine и LiteLLM

Статус

Принято (Реализовано и протестировано)

Контекст и проблематика

Требуется развернуть локальную инфраструктуру для работы большой языковой модели Qwen3.8-Flash-Next (125B параметров, квантование IQ3_S) в условиях жестких аппаратных ограничений: * Оборудование: Виртуальная машина Ubuntu, 65 ГБ RAM, 1 GPU Tesla P100 (16 ГБ VRAM). * Клиенты: Одновременные запросы от IDE (OpenCode) для автодополнения кода, а также от автономных агентов (ROS 2, ESP-IDF Tools) с отправкой объемных логов сборки и кинематики. * Проблема: Нехватка видеопамяти заставляет выгружать часть весов и KV-кэш в системную оперативную память. Без строгих лимитов конкурентные запросы или длинные логи агентов приводят к исчерпанию RAM и принудительному завершению процессов ядром ОС (OOM Killer).

Принятые решения

Решение 1: Шлюз API и управление очередями (LiteLLM + Redis + PostgreSQL)

Для маршрутизации трафика и защиты от одновременных тяжелых вычислений внедрен API-шлюз. * LiteLLM: Выступает единой точкой входа (Port 4000), маскируясь под OpenAI API. Запрещает параллельные запросы к тяжелой модели (max_parallel_requests: 1), защищая VRAM. * Redis: Используется для буферизации запросов. Если Strata Engine занят, новые запросы от агентов и IDE ставятся в очередь, предотвращая сброс соединений по тайм-ауту. * PostgreSQL: Хранит профили пользователей, API-ключи, квоты и историю списаний виртуального бюджета.

Решение 2: Жесткое квотирование памяти (Strata Engine)

Для предотвращения OOM-сбоев и сохранения высокой скорости вывода (Tokens per Second) применены строгие ограничения на уровне движка (Port 8081). * Ограничение контекста (--max-context 65536): Лимит контекстного окна установлен на 64K токенов. * Ограничение резидентного кэша (--kv-resident 16384): Только 16K токенов KV-кэша удерживаются в VRAM видеокарты. Это освобождает ~9.2 ГБ VRAM для кэширования экспертов 125B модели, обеспечивая среднюю скорость генерации около 28-30 tok/s. * Резервирование RAM (--conversation-cache-min-free-mib 6144): Движку запрещено занимать последние 6 ГБ оперативной памяти. Этот объем жестко зарезервирован для стабильной работы Ubuntu и Docker-контейнеров.

Решение 3: Спекулятивное декодирование (Draft Model)

Для ускорения генерации программного кода (где высока предсказуемость синтаксиса) используется техника спекулятивного декодирования. * Легкая черновая модель (0.5B - 1.5B параметров) загружается исключительно на процессор (-ngl 0, --aux-cpus 4), чтобы не расходовать VRAM Tesla P100. * Глубина спекуляции увеличена для кода (--spec 5), что снижает нагрузку на шину PCIe Gen3.

Решение 4: Сдвиг контекста (--ctx-shift on)

Вместо полного обнуления памяти и дорогостоящего пересчета всего массива токенов (Recompute) при достижении лимита в 64K, активирован алгоритм Context Shift. Самые старые логи удаляются скользящим окном, сохраняя системный промпт (инструкции агентов) нетронутым.

Решение 5: Отказ от автоматических профилей

Принято решение принудительно отключить экспериментальные алгоритмы (STRATA_KVA: off) и профили разработчиков (STRATA_DEFAULTS: off). Использование дефолтных настроек на системах с RAM-offload доказано приводит к игнорированию безопасных лимитов и падению сервера по памяти.

Последствия (Consequences)

Положительные:

  1. Высокая стабильность: Полностью устранены OOM-падения. Инфраструктура может работать 24/7.
  2. Предсказуемая производительность: Удержание экспертов в VRAM позволило зафиксировать скорость генерации на уровне ~30 tok/s для сложной 125B модели.
  3. Контроль затрат: Внедрение PostgreSQL и LiteLLM позволяет выдавать агентам и разработчикам изолированные квоты и анализировать потребление токенов.
  4. Удобство: Пользователи имеют доступ к Open-WebUI и встроенному Customer Portal для отслеживания баланса.

Отрицательные (Компромиссы):

  1. При холодном чтении максимального контекста (64K токенов без кэша) возможны задержки отклика (Time-To-First-Token) свыше 1 минуты из-за ограниченной пропускной способности RAM.
  2. Сложность стека: Требуется мониторинг нескольких Docker-контейнеров (LiteLLM, Redis, Postgres, WebUI) и системного процесса Strata Engine. ```eof
